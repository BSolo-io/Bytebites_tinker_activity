# ByteBites Reference File

## About This Project
You are building the backend logic for a campus food ordering app called ByteBites
using Python classes and simple algorithms.

## Project Scope
Do not add authentication logic, a database layer, or any features not described 
in the spec.

## Behavioral Instructions
- Stay within four core classes: `Customer`, `MenuItem`, `Menu`, and `Order`. Don't introduce new classes (e.g. `Payment`, `Discount`, `Kitchen`) unless the spec is updated to ask for them.
- Keep methods simple and direct — plain loops, list comprehensions, and basic arithmetic. Avoid design patterns, inheritance hierarchies, or abstraction layers that aren't needed for four small classes.
- No persistence: data lives in memory only (plain lists/attributes). No files, no ORM, no serialization.
- No authentication, sessions, or user verification beyond what's naturally expressed through purchase history.
- When proposing changes, show the plain Python class/method, not a framework-based implementation (no Flask routes, no Django models, etc.) unless explicitly asked.
